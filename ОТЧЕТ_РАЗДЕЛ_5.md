# 5. Выполнение практической работы

В рамках разработки мобильного приложения «ShareNear», предназначенного для обмена вещами между соседями с акцентом на экологическую ответственность, выполнена интеграция двух внешних сервисов, обеспечивающих расширенную функциональность:

•	сервис геокодинга и поиска адресов – Nominatim API (OpenStreetMap);

•	API для доступа к энциклопедии Wikipedia – Wikipedia API (MediaWiki).

**json_serializable: ^6.7.1**: кодогенератор, создающий реализации методов преобразования объектов в JSON и из JSON на основе аннотаций json_annotation. ## 5.3 Nominatim API

### 5.3.1 Описание выбранного API

•	Базовый URL: https://nominatim.openstreetmap.org

•	Документация: https://nominatim.org/release-docs/latest/api/Overview/

•	Описание: Nominatim — это сервис геокодинга, предоставляемый проектом OpenStreetMap. Сервис позволяет преобразовывать адреса в географические координаты (прямой геокодинг) и выполнять обратные операции, а также осуществлять поиск адресов и географических объектов по различным критериям. Nominatim использует данные OpenStreetMap, которые создаются и поддерживаются сообществом добровольцев по всему миру, что обеспечивает широкое покрытие и актуальность информации.

•	Основные возможности:

- Преобразование адресов в координаты (прямой геокодинг);

- Поиск адресов по текстовому запросу;

- Поиск адресов с фильтрацией по городу или стране;

- Поиск географических объектов по типу и местоположению.

### 5.3.1.1 Внедрение в приложение и демонстрация работы первого сетевого запроса

HTTP-метод: GET /search

Базовый URL: https://nominatim.openstreetmap.org

Назначение:

Метод предназначен для преобразования текстового адреса в географические координаты (широту и долготу). Эта операция необходима для сохранения местоположения объявления в структурированном виде, что в дальнейшем позволяет использовать координаты для отображения на карте, вычисления расстояний или фильтрации объявлений по географической близости.

Параметры запроса:

•	q (обязательный, строка) — текстовое описание адреса, которое требуется преобразовать в координаты. Может содержать название улицы, номер дома, город, страну или любую комбинацию этих элементов.

•	format (обязательный, строка) — формат ответа, в данном случае используется значение "json" для получения структурированных данных.

•	limit (необязательный, целое число) — максимальное количество результатов в ответе. Для геокодинга обычно устанавливается значение 1, так как требуется получить наиболее релевантный результат.

Логика работы в приложении:

При создании нового объявления пользователь может указать адрес в соответствующем поле формы. При нажатии кнопки сохранения объявления приложение вызывает метод geocodeAddress из GeocodingCubit, который формирует GET-запрос к эндпоинту https://nominatim.openstreetmap.org/search с параметром q, содержащим введённый адрес, и параметром limit=1 для получения одного наиболее подходящего результата.

Nominatim API обрабатывает запрос и возвращает JSON-ответ, содержащий координаты найденного адреса, его отображаемое название и детальную структурированную информацию об адресе. Данные преобразуются из формата DTO в кортеж координат (широта, долгота) с помощью GeocodeAddressUseCase и NominatimMapper, после чего сохраняются вместе с остальными данными объявления в локальной базе данных.

### 5.3.1.2 Внедрение в приложение и демонстрация работы второго сетевого запроса

HTTP-метод: GET /search

Базовый URL: https://nominatim.openstreetmap.org

Назначение:

Запрос предназначен для поиска адресов по произвольному текстовому запросу с целью предоставления пользователю списка подходящих вариантов во время ввода. Это реализует функциональность автодополнения, которая помогает пользователю быстрее и точнее указать адрес, уменьшая вероятность ошибок при вводе и улучшая общий пользовательский опыт.

Параметры запроса:

•	q (обязательный, строка) — текстовый запрос для поиска адресов. Может содержать часть названия улицы, города, достопримечательности или любой другой географический объект.

•	format (обязательный, строка) — формат ответа, устанавливается в значение "json".

•	limit (необязательный, целое число) — ограничение на количество возвращаемых результатов. В приложении используется значение 5 для отображения наиболее релевантных вариантов без перегрузки интерфейса.

Логика работы в приложении:

## 5.4 Wikipedia API

### 5.4.1 Описание выбранного API

•	Базовый URL: https://ru.wikipedia.org/w/api.php

•	Документация: https://www.mediawiki.org/wiki/API:Main_page

•	Описание: Wikipedia API (MediaWiki API) — это программный интерфейс для доступа к содержимому и метаданным статей энциклопедии Wikipedia. API предоставляет возможность поиска статей, получения их содержимого, работы с категориями, извлечения связанных статей и изображений. В приложении используется русскоязычная версия Wikipedia, что обеспечивает релевантность информации для русскоязычных пользователей и соответствие тематике экологии и переработки отходов.

•	Основные возможности:

- Поиск статей по текстовому запросу;

- Получение содержимого статей с извлечённым текстом;

- Получение списка статей из определённой категории;

- Получение списка статей, связанных с указанной статьёй;

- Получение списка изображений, используемых в статье.

### 5.4.1.1 Внедрение в приложение и демонстрация работы первого сетевого запроса

HTTP-метод: GET /w/api.php

Базовый URL: https://ru.wikipedia.org

Назначение:

Метод предназначен для поиска статей в энциклопедии Wikipedia по произвольному текстовому запросу. Это позволяет пользователям находить информацию об экологии, переработке отходов и других темах, связанных с экологической ответственностью. Поиск выполняется по названиям статей, их содержимому и метаданным, что обеспечивает широкий охват релевантных результатов.

Параметры запроса:

•	action (обязательный, строка) — действие API, устанавливается в значение "query" для запроса данных.

•	list (обязательный, строка) — тип списка для получения, устанавливается в "search" для выполнения поиска.

•	srsearch (обязательный, строка) — текстовый запрос для поиска статей. Может содержать ключевые слова, названия тем или любые другие текстовые фрагменты.

•	srlimit (необязательный, целое число) — максимальное количество результатов в ответе, по умолчанию 5.

•	format (обязательный, строка) — формат ответа, значение "json".

•	srnamespace (необязательный, целое число) — пространство имён для поиска, устанавливается в 0 для ограничения поиска только основными статьями (исключая служебные страницы, обсуждения и другие типы страниц).

Логика работы в приложении:

Приложение формирует GET-запрос к эндпоинту https://ru.wikipedia.org/w/api.php с параметрами action=query, list=search, srsearch, содержащим введённый запрос, и srlimit=5 для ограничения количества результатов.

Wikipedia API обрабатывает запрос и возвращает JSON-ответ, содержащий список найденных статей с их идентификаторами, названиями и фрагментами текста (snippet), которые содержат вхождения поискового запроса. Данные преобразуются из DTO в доменные модели EcoTipModel через SearchWikipediaArticlesUseCase и WikipediaMapper, после чего отображаются в виде списка карточек с названиями статей и краткими описаниями.

•	exintro (необязательный, целое число) — флаг для получения только вводной части статьи, устанавливается в 1 для ограничения объёма текста.

•	explaintext (необязательный, целое число) — флаг для извлечения текста без HTML-разметки, устанавливается в 1 для получения чистого текста.

•	format (обязательный, строка) — формат ответа, значение "json".

•	pithumbsize (необязательный, целое число) — размер миниатюры изображения в пикселях, устанавливается в 200 для получения небольшого превью.

Логика работы в приложении:

Пользователь нажимает на карточку статьи в списке результатов поиска или вводит точное название статьи в соответствующее поле на экране "Эко-гид". При подтверждении действия вызывается метод getWikipediaPageContent из EcoGuideCubit. Приложение формирует GET-запрос к эндпоинту https://ru.wikipedia.org/w/api.php с параметрами action=query, prop=extracts|pageimages, titles, содержащим название статьи, и флагами exintro=1 и explaintext=1 для получения вводной части в текстовом формате.

Wikipedia API возвращает JSON-ответ с содержимым статьи, включая извлечённый текст и информацию о миниатюре изображения (если она доступна). Данные преобразуются в объект EcoTipModel через GetWikipediaPageContentUseCase и WikipediaMapper, после чего отображаются в интерфейсе с полным текстом статьи и изображением, что позволяет пользователю ознакомиться с подробной информацией по выбранной теме.

### 5.4.1.3 Внедрение в приложение и демонстрация работы третьего сетевого запроса

HTTP-метод: GET /w/api.php

Базовый URL: https://ru.wikipedia.org

Назначение:

Запрос позволяет получить список статей, принадлежащих определённой категории Wikipedia. Это особенно полезно для тематического изучения информации, когда пользователь хочет ознакомиться со всеми статьями, связанными с конкретной областью знаний, например, "Экология" или "Переработка отходов". Функциональность используется в экране деталей объявления для автоматической загрузки статей, относящихся к категории товара.

Параметры запроса:

•	action (обязательный, строка) — действие API, значение "query".

•	list (обязательный, строка) — тип списка, устанавливается в "categorymembers" для получения членов категории.

•	cmtitle (обязательный, строка) — название категории в формате "Категория:{название}". Если название уже содержит префикс "Категория:", оно используется как есть, иначе префикс добавляется автоматически.

•	cmlimit (необязательный, целое число) — максимальное количество статей в ответе, по умолчанию 10.

•	format (обязательный, строка) — формат ответа, значение "json".

•	cmnamespace (необязательный, целое число) — пространство имён для фильтрации, устанавливается в 0 для получения только основных статей.

Логика работы в приложении:

При открытии экрана деталей объявления пользователь может раскрыть секцию "Информация об экологии". При раскрытии секции автоматически вызывается метод getWikipediaCategoryArticles из EcoGuideCubit. Название категории формируется на основе категории товара: для товара категории "Электроника" используется категория "Электроника", для "Одежда" — "Одежда" и так далее. Приложение формирует GET-запрос к эндпоинту https://ru.wikipedia.org/w/api.php с параметрами action=query, list=categorymembers, cmtitle, содержащим название категории с префиксом "Категория:", и cmlimit=5 для получения ограниченного списка статей.

Wikipedia API возвращает JSON-ответ со списком статей из указанной категории, каждая из которых содержит идентификатор страницы и название. Данные преобразуются в список объектов EcoTipModel через GetWikipediaCategoryArticlesUseCase и WikipediaMapper, после чего отображаются в виде элементов списка внутри раскрывающейся секции. Это позволяет пользователю быстро получить доступ к релевантной информации об экологии и переработке, связанной с категорией рассматриваемого товара.

Базовый URL: https://ru.wikipedia.org

Назначение:

### 5.4.1.5 Внедрение в приложение и демонстрация работы пятого сетевого запроса

HTTP-метод: GET /w/api.php

Базовый URL: https://ru.wikipedia.org

Назначение:

Запрос предназначен для получения списка изображений, используемых в указанной статье Wikipedia. Изображения могут включать фотографии, диаграммы, схемы и другие визуальные материалы, которые помогают лучше понять содержание статьи. Функциональность используется в экране "Руководство по переработке" для визуального дополнения информации о различных категориях отходов и способах их переработки.

Параметры запроса:

•	action (обязательный, строка) — действие API, значение "query".

•	prop (обязательный, строка) — свойства страницы, устанавливается в "images|imageinfo" для получения списка изображений и их детальной информации.

•	titles (обязательный, строка) — точное название статьи, для которой требуется получить список изображений.

•	imlimit (необязательный, целое число) — максимальное количество изображений в первом запросе, по умолчанию 10.

•	format (обязательный, строка) — формат ответа, значение "json".

•	iiprop (необязательный, строка) — свойства изображений для получения, устанавливается в "url|size" для получения URL изображений и их размеров.

Логика работы в приложении:

При выборе категории отходов на экране "Руководство по переработке" автоматически вызывается метод getWikipediaPageImages из EcoGuideCubit. Название статьи формируется на основе выбранной категории: для категории "Электроника" используется статья "Электроника", для "Одежда" — "Одежда" и так далее. Приложение выполняет два последовательных запроса: сначала отправляется GET-запрос к эндпоинту https://ru.wikipedia.org/w/api.php с параметрами action=query, prop=images, titles для получения списка названий изображений, затем формируется второй запрос с параметрами action=query, prop=imageinfo, titles, содержащими названия изображений, разделённые символом "|", для получения детальной информации, включая URL и размеры.

Wikipedia API возвращает JSON-ответы: первый содержит список названий изображений, второй — детальную информацию об этих изображениях с URL и размерами. Данные преобразуются в список объектов EcoTipModel через GetWikipediaPageImagesUseCase и WikipediaMapper, после чего изображения отображаются в виде горизонтального прокручиваемого списка над описанием шагов по переработке. Это обеспечивает визуальное дополнение текстовой информации и улучшает восприятие материала пользователем.

ВЫВОД

В ходе выполнения практической работы по дисциплине «Разработка кроссплатформенных мобильных приложений» была реализована интеграция двух внешних API в мобильное приложение «ShareNear»: Nominatim API для геокодинга и поиска адресов, а также Wikipedia API для получения информации об экологии и переработке отходов. Сетевой слой спроектирован в соответствии с принципами чистой архитектуры: все HTTP-запросы выполняются через источники данных, использующие библиотеку Dio, а данные преобразуются из DTO в доменные модели с помощью мапперов. Обработка ошибок и логирование централизованы через интерсепторы.

Функциональность интегрирована в основные экраны приложения: экран создания объявления использует геокодинг для сохранения координат, экран эко-гида предоставляет доступ к информации из Wikipedia, экран деталей объявления автоматически загружает релевантные статьи по категории товара. Управление состоянием реализовано с применением паттерна BLoC, обеспечивая чёткое разделение логики и пользовательского интерфейса. Работа демонстрирует умение интегрировать сторонние API, проектировать масштабируемый сетевой слой и создавать удобный пользовательский интерфейс в рамках современной архитектуры Flutter-приложений.
